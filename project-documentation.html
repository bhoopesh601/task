Section 01

Project Overview

Purpose, objectives, and key features of the Todo Application

Purpose & Problem Statement

The React Todo Application is a modern, full-featured task management web application built as a front-end only project using React 19 and Vite 8. It addresses the everyday problem of organizing and tracking personal tasks efficiently — without needing a backend server. All data is persisted in the browser's localStorage, making the app fully offline-capable.

The application demonstrates real-world React patterns including component composition, custom hooks, Context API for global state, protected routing, and responsive CSS design — making it ideal as an internship submission, college project, or GitHub portfolio piece.

Main Objectives

🎯 Build a complete CRUD application using React
🔐 Implement simple user authentication flow
🗂️ Demonstrate React Context API for state management
🔄 Use React Router DOM for client-side navigation
💾 Persist data with localStorage — no backend needed
📱 Create a fully responsive and accessible UI
🌗 Implement dark / light mode theming
⚡ Use Vite for fast development experience

Login.jsx — User Authentication Page

The Login page is the application's entry point. It renders a styled login form with an email and password input. On submit, the login(email) function from AuthContext is called, which stores a session object in localStorage. On success, React Router automatically redirects to /dashboard via the PublicRoute guard. If a user is already authenticated, they are immediately redirected away from this page.

User Flow: Open App → Login Form → Enter Email + Password → Click Login → Redirect to Dashboard

Dashboard.jsx — Main Application Screen

The Dashboard is the protected main screen where all todo management happens. It renders: <Navbar />, <Stats />, <SearchBar />, <TodoForm />, and the list of <TodoCard /> components. It consumes processedTodos from TodoContext to render the filtered, searched, and sorted list. The ProtectedRoute wrapper redirects unauthenticated users to /.

Key Behavior: The page re-renders reactively when any todo is added, updated, deleted, or when search/filter/sort controls change — powered by React Context and useMemo.

NotFound.jsx — 404 Error Page

Rendered for any URL that does not match / or /dashboard. It displays a friendly 404 message and a link back to the home page, improving user experience and preventing blank screens on invalid routes.

Section 06

Context & State Management

Global state architecture using React's built-in Context API

Architecture: Two separate contexts — AuthContext for authentication and TodoContext for todo data — are both wrapped at the root level in App.jsx to make their values available throughout the entire component tree without prop drilling.

AuthContext.jsx — Authentication State

src/context/AuthContext.jsx Created

Purpose & Responsibilities

  • Creates and exports AuthContext using React.createContext()
  • Wraps children in AuthProvider exposing user, isAuthenticated, login(), logout()
  • Uses useLocalStorage hook to persist the session under key 'authUser'
  • The login(email) function creates a user object: { email, loggedInAt }
  • The logout() function clears the user to null, destroying the session
  • Exports useAuth() custom hook for easy consumption in any component
  • Uses useMemo to prevent unnecessary re-renders of the context value

Exported Values

ExportTypeDescription
userObject | nullCurrent user data or null if not logged in
isAuthenticatedBooleanDerived from !!user
login(email)FunctionSaves user session to localStorage
logout()FunctionClears user session from localStorage

TodoContext.jsx — Todo State Management

src/context/TodoContext.jsx Created

Purpose & Responsibilities

  • Creates and exports TodoContext and the TodoProvider component
  • Persists all todos in localStorage under key 'todos' via useLocalStorage
  • Manages searchQuery, activeFilter, and sortBy state variables
  • Implements full CRUD: addTodo(), updateTodo(), deleteTodo(), toggleStatus()
  • Computes processedTodos via useMemo — applies search → filter → sort in sequence
  • Computes stats object (total, completed, pending, highPriority) via useMemo
  • Manages toast notification state with auto-dismiss after 3 seconds
  • All mutation functions wrapped in useCallback for stable references and performance

Key Exported Values

ExportTypeDescription
todosArrayRaw todos array from localStorage
processedTodosArrayFiltered, searched & sorted todos for display
statsObject{ total, completed, pending, highPriority }
addTodo(data)FunctionCreates a new todo with auto-generated ID
updateTodo(id, data)FunctionMerges updated fields into existing todo
deleteTodo(id)FunctionRemoves todo by ID
toggleStatus(id)FunctionFlips Pending ↔ Completed
toast / showToast()Object / FunctionToast notification state and trigger

Key File: App.jsx — Root Component

Original State: Vite scaffolds a default App.jsx with a counter demo and Vite/React logos.
Changes Made: Completely replaced with the application root. Added AuthProvider and TodoProvider context wrappers, and BrowserRouter with a nested AppRoutes component using useRoutes(routeConfig).
Why: The app needs global providers at the top level so any component in the tree can access auth and todo state without prop drilling.

Key File: useLocalStorage.js — Custom Hook

A custom React hook that works like useState but automatically reads the initial value from localStorage and writes every state update back. This single hook powers both AuthContext (persisting the user session) and TodoContext (persisting all todos), keeping both contexts clean and focused on business logic rather than storage mechanics.

Key File: helpers.js — Utility Functions

  • generateId() — Creates a unique ID for new todos using Date.now() + random suffix
  • sampleTodos — Initial demo todos loaded on first run when localStorage is empty
  • sortTodos(arr, sortBy) — Sorts by date (latest/oldest) or by priority level
  • filterTodos(arr, filter) — Filters by 'all', 'pending', or 'completed' status
  • searchTodos(arr, query) — Case-insensitive search across title and description fields
Section 08

Application Workflow

Complete user journey from application launch to logout

Step 01
🚀 User Opens Application

Browser loads index.html. Vite injects main.jsx which calls ReactDOM.createRoot() and renders <App />. Context providers initialize and the router renders the / route.

Step 02
🔐 Login Authentication

The PublicRoute checks isAuthenticated from AuthContext. If no session exists, Login.jsx is rendered. User enters email and password; on submit, login(email) saves the session to localStorage.

Step 03
📋 Redirect to Dashboard

After login, isAuthenticated becomes true. The PublicRoute detects this and issues <Navigate to="/dashboard">. Dashboard renders with existing todos loaded from localStorage.

Step 04
➕ Add New Todo

User fills TodoForm with title, description, priority, category, and due date. On submit, addTodo(data) prepends a new todo with auto-generated ID and timestamp. A success toast appears and the card renders immediately.

Step 05
👁️ View Todos

Dashboard maps over processedTodos to render one TodoCard per todo, displaying title, description, priority badge, category, due date, and status.

Step 06
🔍 Search & Filter Todos

User types in SearchBar to update searchQuery. Clicking filter buttons updates activeFilter. Changing sort dropdown updates sortBy. processedTodos is recomputed by useMemo and the list updates instantly.

Step 07
✏️ Update Todo

User clicks Edit on a TodoCard. TodoForm enters edit mode with all fields pre-populated. On submit, updateTodo(id, data) merges the changes and shows an update toast.

Step 08
🗑️ Delete Todo

User clicks Delete on a TodoCard. A Modal confirmation dialog appears. If confirmed, deleteTodo(id) filters out the todo. If cancelled, nothing changes. A danger toast confirms the deletion.

Step 09
🌗 Change Theme

User clicks ThemeToggle in the Navbar. The component toggles data-theme on <html> between dark and light. CSS custom properties cascade and the entire UI re-themes instantly. Preference saved to localStorage.

Step 10
🚪 Logout

User clicks Logout in the Navbar. logout() sets user to null and clears localStorage. isAuthenticated becomes false. ProtectedRoute detects this and redirects back to the Login page.

CSS Custom Properties — Theme System

The dark/light theme system uses CSS Custom Properties (variables). The [data-theme="dark"] and [data-theme="light"] selectors on <html> override a set of base variables. Every component uses these variables — no hardcoded colors anywhere.

CSS — global.css (excerpt)

  --bg-primary:     #ffffff;
  --bg-secondary:   #f8fafc;
  --text-primary:   #0f172a;
  --text-secondary: #64748b;
  --accent-color:   #4f46e5;
  --border-color:   #e2e8f0;
  --card-shadow:    0 4px 16px rgba(0,0,0,0.06);
}

[data-theme="dark"] {
  --bg-primary:     #0f172a;
  --bg-secondary:   #1e293b;

Dark Mode Implementation

  • ThemeToggle.jsx reads initial theme from localStorage.getItem('theme')
  • On toggle, calls document.documentElement.setAttribute('data-theme', newTheme)
  • CSS variables under [data-theme="dark"] override light defaults instantly
  • No JavaScript color computation — pure CSS variable cascading ensures flicker-free switching
  • Preference saved via localStorage.setItem('theme', newTheme)
